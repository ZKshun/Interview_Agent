# 设计

## 整体架构

前后端分离
- Vue 3 前端：只负责上传面试信息和资源文件、展示和交互
- NodeJS 后端：负责所有解析、生成、去重、校验逻辑
重点在服务端的设计！

## 项目两大模块

### 模块一：生成面试官直接用的面试题
直接跑一边核心链路层的解析+规划生成，不进入向量去重层，得到面试题之后，面试官可在前端题卡进行在线编辑确认

### 模块二：生成候选人笔试题


## 核心链路拆解

### 多格式解析层（NodeJS）

用户上传的资料可能是 PDF 简历、DOCX 面经、粘贴的文本。Node.js 侧按文件类型分发到不同解析器：
- PDF - pdf-parse
- DOCX - mammoth
- 纯文本/粘贴 - 直接读取
关键设计点：解析结果保留来源标签（如“简历_项目经历”“面经_面经原文”），后续生成题目时可以根据来源调整提问角度。

### 知识点规划与题目生成（LangChain + Zod）- 面试题

采用先规划再生成的分步实现方式：
1. 规划：让 LLM 根据解析文本提取“可提问的知识点”列表（覆盖技术栈、难点、量化数据、架构决策等方向），输出结构化数据
> 结构化数据：需要从提示词要求 - LLM 底层 - 外部 Zod 校验进行多重的结构化验证 
2. 生成：让 LLM 针对每一个知识点生成 2-3 道面试题，并附带参考答案要点和纠察方向

### 简历整体规划与题目描述生成（LangChain + Zod）- 笔试题

同样是规划 + 生成的两步实现方式：
1. 整体规划：根据简历 + 岗位 JD 编号 + 输入要求整理出 N 道题目的生成描述提示词
2. 向量去重层（Milvus）
    - 题目生成前，将所有的 Prompt 向量化之后进入向量题库进行相似度识别，高于阈值的 Prompt 对于的题目需要可以直接使用
    - 题目生成之后，将完整题目向量化之后存入题库
2. 提示词生成：让 LLM 根据提示词 + 异步队列生成题目


## 🎴 前端题卡编辑（Vue 3）

前端不需要复杂。核心页面就两个：
1. 信息输出/资料上传页：模式选择（面试题生成 / 笔试题生成） -> 选择文件 + 信息输入区域 -> （按钮）下一步：开始解析 -> 进入解析页
2. 解析页：直接流式展示出解析的完整过程，并需要 MD 格式的前端显示转化 -> （按钮）解析完毕，点击进行规划生成
3. 规划生成页：流式展示规划生成的 LLM 输出 -> 完成之后跳转前端题卡
4. 题卡列表页：展示生成的结构化题目卡片，支持手动编辑题干、删除不想要的题、标记难度。Pinia 管理题目列表状态即可。


# 核心问题

模块一的生成过于“裸奔”（缺乏质量自检），模块二的去重逻辑时机倒置（Prompt 去重直接复用题目有风险），以及整体缺乏流程的“状态管理”。


融合下面三种工程化思想：

1、将每个步骤拆为单独节点，用状态机管理整个生成过程，强调流程可控：
将“解析资料→提取知识点→生成题目→向量去重”做成四个节点，如果某个节点出错就只需要重跑该节点即可，而不是整条链路重来

2、多 Agent 分工 + 评分机制闭环，强调质量：
单次 LLM 生成的质量不稳定，用评分-打回机制把 “生成” 变成 “生成 + 筛选”，最终输出给用户的题目通过率更高

3、RAG，强调有据可依
优先建立一个小型的 “优质面试题库”，生成新题时先检索 N 道已有题目作为 few-shot 示例注入 Prompt
